# CapriCore-Linux 2.0.0-alpha.1

The first release of the Linux fork, based on upstream Capri 1.2.2. It is a
pre-release: it runs from source on Linux, and several features still wait for
Linux backends.

## Linux port

- Windows code, the Windows installer and the updater's install path are gone.
  Hardware probing, process load and file locations have Linux backends.
- The companion window opens on Wayland (developed on sway), stays clickable and
  moves by its header. A native layer-shell avatar overlay lives in `apps/overlay`.
- Speech setup is ported from PowerShell to Node, with a pinned, uv-managed
  Python per component.
- `npm run claude-bridge` lets Capri chat through a signed-in Claude Code CLI
  with no model download. API mode starts without llama.cpp.
- Update checks read this fork's GitHub releases. A git checkout is offered newer
  tagged releases and updates with `git pull`; pre-releases appear only on the
  experimental channel.

## Scope

Upstream side features were removed so Capri stays a desktop companion: chess,
coding mode, Spotify, YouTube Music, music listening, Steam, Discord presence and
control, recorded workflows, the private GitHub token flow and the
screen-reading click/type computer agent. Computer control now opens permitted
apps and web pages and types into inspected fields. Russian language support was
removed. The interface ships in English, French, Polish and Ukrainian.

## Security

Code inherited from upstream was audited; see
[the audit report](../linux/security-audit-2026-11-27.md). The updater no
longer sends a GitHub CLI or environment token, the speech recognition lock
now carries hashes, and the ProxyAPI preset is gone.

One finding is still open: the voice dependency locks
(`requirements-voice-amd.lock`, `requirements-voice-blackwell.lock` and
`requirements-voice-training.lock`) pin versions but have no `--hash` entries,
so a re-uploaded or tampered package would not be caught. They target Windows
and get hashes when they are rebuilt for Linux, the same work that makes voice
output installable.

## Known limits

- Voice output does not install yet: the voice, router and Qwen dependency locks
  are still Windows builds. Speech recognition installs.
- App actions, screen capture, app awareness, call audio, the virtual camera and
  the user-tool sandbox report "not available on Linux yet".
- Memory recall needs a system `llama-server` and the embedding model.
- No packages or installer: run from source with `npm ci`, `npm run setup` and
  `npm run desktop`.
